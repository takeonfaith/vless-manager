# vless-manager

Одна команда для установки личного **VLESS + REALITY** VPN и управления устройствами. На сервере работает Xray-core; VLESS — протокол подключения, REALITY — защита транспорта. Ссылки `vless://` можно импортировать в Happ и другие клиенты с поддержкой VLESS + REALITY + Vision.

## Новый сервер

Поддерживаются Ubuntu 22.04/24.04/26.04 и Debian 12/13, systemd, архитектуры x86_64 и arm64. Нужны root-доступ, публичный IPv4 либо DNS с A-записью и доступ к GitHub для загрузки Xray. Ориентир для личного сервера: 1 vCPU, 1 ГБ RAM и 10–15 ГБ диска. Контейнер без systemd, Windows и macOS как серверы этим установщиком не поддерживаются.

Подключись по SSH к **новому VPS** и выполни от root (или добавь `sudo` к командам установки и управления):

```bash
apt-get update && apt-get install -y git
git clone https://github.com/takeonfaith/vless-manager.git
cd vless-manager
bash install.sh
vless-manager setup --host YOUR_SERVER_IP
vless-manager add iphone
```

Замени `YOUR_SERVER_IP` на внешний IPv4 VPS. Последняя команда выдаст ссылку: скопируй её целиком и импортируй в Happ. Для каждого устройства лучше создавать отдельное имя — тогда его доступ можно отозвать независимо.

Входящий **TCP 443** должен быть разрешён в firewall сервера **и в панели хостинга**. Менеджер не включает, не выключает и не переписывает firewall. Если UFW уже активен, добавь `ufw allow 443/tcp`; не включай UFW без разрешения SSH. UDP-порт для этой конфигурации не требуется.

Другой порт и свой REALITY SNI:

```bash
vless-manager setup --host YOUR_SERVER_IP --port 8443 --sni www.bing.com
```

SNI — доступный с VPS сайт с TLS 1.3, HTTP/2 и подходящим сертификатом; `setup` проверяет эти свойства. Это не домен, который нужно покупать или направлять на VPS. По умолчанию используется `www.bing.com`, как в исходной конфигурации. Подходящий SNI не гарантирует доступность из конкретной сети: после установки проверь VPN со своего интернета.

## Ежедневные команды

```bash
vless-manager add iphone           # добавить устройство, вывести VLESS-ссылку
vless-manager add laptop
vless-manager list                 # имена устройств, без UUID и ключей
vless-manager link iphone          # повторно получить ту же ссылку
vless-manager remove iphone        # отозвать доступ с подтверждением
vless-manager remove laptop --yes  # без интерактивного вопроса
vless-manager status
vless-manager check
vless-manager logs
vless-manager restart
vless-manager set-host NEW_IP      # обновить адрес в выдаваемых ссылках
```

Имена: латинские буквы, цифры, дефис и подчёркивание, до 64 символов. Регистр при поиске и проверке дубликатов не учитывается. `add` с уже существующим именем завершается ошибкой и не заменяет ключ. После повторного добавления удалённого имени выдаётся новый UUID.

**Добавление и удаление не перезапускают Xray:** изменения применяются через локальный HandlerService API и сохраняются в JSON для следующей загрузки сервера. Существующие подключения других устройств продолжают работать, включая SSH через этот VPN. Удаление запрещает новые подключения устройства; уже открытые соединения могут работать до их закрытия. Если нужно немедленно оборвать вообще все соединения, отдельно выполни `vless-manager restart` — это прервёт VPN у всех пользователей.

После `set-host` нужно заново импортировать ссылки на устройствах; команда меняет только адрес в ссылках, не переносит сервер и не меняет DNS.

## Обновление с версии 1.0

```bash
cd /root/vless-manager  # либо твой каталог клонированного репозитория
git pull --ff-only
bash install.sh
vless-manager enable-api
```

`enable-api` сохраняет ключи и пользователей, включает API и **один раз перезапускает Xray**. Если твоя SSH-сессия проходит через этот VPN, запусти переход как отдельную службу, чтобы обрыв туннеля не прервал команду:

```bash
systemd-run --unit=vless-enable-api --collect --on-active=3s /usr/local/bin/vless-manager enable-api
```

Через несколько секунд переподключись к VPN/SSH и проверь `vless-manager status`. Повторный `enable-api` только проверяет API, без перезапуска. Новая установка через `setup` включает API сразу. Без доступного API команды `add`/`remove` завершаются ошибкой; скрытого перехода к перезапуску службы нет.

API слушает **только 127.0.0.1:10085**, открывать этот порт в firewall не нужно. Первое правило маршрутизации запрещает проксировать TCP на этот порт: клиенты VPN не смогут обратиться к API через VPN, в том числе через DNS-имя, указывающее на loopback. Это также запрещает проксирование на порт 10085 любых других адресов. Для другого порта используй `setup --api-port PORT` либо `enable-api --port PORT` при первом включении. Локальные процессы на VPS считаются доверенными: сам Xray API не имеет аутентификации. Существующие чужие настройки API менеджер не перезаписывает.

## Уже установлен Xray

`setup` отказывается перезаписывать обнаруженный Xray. Вместо него после установки менеджера выполни:

```bash
vless-manager adopt --host YOUR_SERVER_IP \
  --config /usr/local/etc/xray/config.json \
  --binary /usr/local/bin/xray \
  --service xray
vless-manager enable-api
vless-manager list
vless-manager add new-phone
```

`adopt` проверяет конфиг и systemd-службу, затем сохраняет пути для управления. Сам конфиг, UUID, REALITY-ключи и текущие подключения не изменяются. Права существующего конфига сохраняются. Поддерживается обычный JSON-файл, явно указанный в `ExecStart`; JSONC, `-confdir`, панели 3x-ui и Docker-установки не поддерживаются. Если inbound VLESS + REALITY несколько, передай `--tag ИМЯ_INBOUND`. Поддерживаются TCP/RAW и ссылки Vision; XHTTP, gRPC и другие схемы транспорта не входят в этот проект.

Менеджер выбирает inbound по протоколу и тегу, а не по позиции в массиве. Остальные inbound и настройки сохраняются. Старые скрипты `addvpn`/`removevpn` лучше больше не запускать: они не используют блокировку менеджера и могут конфликтовать с его изменениями. Не редактируй JSON одновременно с командами менеджера.

## Что устанавливается

- `/usr/local/bin/vless-manager` — самодостаточный Python-скрипт; сторонние Python-пакеты не нужны.
- `/usr/local/lib/vless-manager/xray` — Xray **26.3.27** из официального релиза. Архив проверяется по SHA-256 из официального `.dgst` через HTTPS. Другая версия: `setup --xray-version X.Y.Z`; совместимость иных версий не гарантируется.
- `/etc/vless-manager/config.json` — конфиг новой установки, root:`vless-xray`, `0640`.
- `/etc/vless-manager/manager.json` — параметры менеджера, root-only (`0600`).
- `vless-manager-xray.service` — отдельная systemd-служба, пользователь `vless-xray`, автозапуск.
- `/var/lib/vless-manager/backups/` — резервные копии перед изменениями, каталог `0700`, файлы `0600`.

Новая установка создаёт новые REALITY-ключи и short ID. Повторный `setup` с теми же параметрами проверяет состояние и сохраняет ключи и пользователей. Это не команда обновления Xray. На новом сервере после `setup` ещё нет пользователей — добавь первого через `add`.

Перед изменением менеджер проверяет временный конфиг самим Xray, сохраняет backup и атомарно заменяет JSON с сохранением владельца и прав. При `add`/`remove` отправляет только изменение одного пользователя и проверяет рабочий список через API: один лишь нулевой код выхода CLI Xray не считается подтверждением. При ошибке восстанавливает файл и, если нужно, отменяет изменение через API, без перезапуска. Если состояние API невозможно подтвердить, явно сообщает об этом; автоматического перезапуска нет. При первоначальном `enable-api` ошибка запуска приводит к восстановлению старого конфига и службы.

Операции менеджера защищены общей файловой блокировкой. Это защита от обычных ошибок, а не транзакция при отключении питания или `kill -9`; резервные копии остаются для ручного восстановления. При аварийном завершении между записью файла и RPC файл и рабочий список могут различаться до следующего запуска Xray; при обнаружении расхождения для изменяемого пользователя команда откажется от операции.

Backup содержит ключи и старые UUID: не публикуй его. Восстановление старого backup может снова разрешить ранее отозванный доступ. Копии не удаляются автоматически; периодически убирай ненужные. VLESS-ссылка также предоставляет доступ к VPN — передавай её только владельцу устройства. Логи могут содержать адреса подключений. В репозиторий не входят конфигурации, ключи или пользователи какого-либо действующего сервера.

При ошибке первоначальной установки созданные этой попыткой конфиг, бинарный файл и служба удаляются. Установленные системные пакеты и служебный пользователь остаются. Существующие VPN, сайты, базы данных и firewall установщик не перенастраивает.

## Проверки

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh
```

Для проверки реального VLESS-туннеля с временными ключами и только loopback-портами:

```bash
XRAY_TEST_BINARY=/usr/local/bin/xray python3 -m unittest discover -s tests -p test_xray_runtime.py -v
```

Этот тест не читает рабочий конфиг и не управляет рабочей службой. Он проверяет новое подключение после добавления, отказ после удаления и сохранение одного и того же открытого TCP-соединения другого пользователя во время обеих операций. Нужен доступ к `www.bing.com:443` для REALITY. GitHub Actions дополнительно выполняет чистую установку, повторный setup и полный цикл устройств с проверкой неизменности PID Xray на Ubuntu 22.04 и 24.04. `tests/smoke_install.py` предназначен **только для одноразовой тестовой VM**: он действительно устанавливает службу.

Официальная документация: [Xray-core](https://github.com/XTLS/Xray-core), [REALITY](https://xtls.github.io/en/config/transports/reality.html).
